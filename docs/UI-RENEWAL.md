# モバイルUIと共有買い物リスト（2026年11月18日）

公開アプリはホーム・冷蔵庫・AI献立・買い物の4画面です。下部ナビで切り替えます。家族設定・アカウントは右上の設定ボタンへ移動しました。

## 機能

- アイボリー、テラコッタ、セージを使った雑誌風のデザイン。ホームのイラスト部分は将来キャラクターを置ける独立した領域です。
- 食材は自動カテゴリ分類、絞り込み、検索、追加・編集・削除に対応。追加と写真登録はシートで開きます。既存食材を削除する必要はありません。
- AI献立は既存のgenerate-dinnerをそのまま使います。旧定番レシピの画面と呼び出しを廃止し、3つの献立カードから詳細を開く方式にしました。詳細は主菜・副菜・汁物を切り替えて表示します。生成プロンプトやサーバーの品質検証は変更していません。
- 買い物は食材以外も自由に登録でき、数量・単位、購入済みチェック、編集・削除に対応します。
- shopping_itemsは現在選択中のhousehold_idに結び付け、既存のis_household_member関数によるRLSで共有します。ログイン前や他世帯からは読み書きできません。
- リアルタイム通知に加え、画面を開いたとき・復帰したとき・20秒間隔の更新で他端末の変更を読み込みます。DELETE通知等を取り逃しても更新できます。

## データベース

`supabase/migrations/202611180001_mobile_and_shopping.sql` を本番に適用しました。食材にはcategory列と世帯メンバー用の更新ポリシーを追加し、新しくshopping_itemsを作成しました。アカウント、共有関係、既存食材、写真認識関数、献立関数は削除・変更していません。

今後、AIの不足食材を追加する場合もshopping_itemsへの登録処理を再利用できます。現時点では、献立から勝手に買い物へ追加する動作はありません。

## 本番での確認結果

- GitHub Pagesの公開成功を確認し、幅約341pxのスマホ相当の表示で4画面の切り替え、ホーム、カテゴリ別の冷蔵庫、入力シートを確認しました。横へのはみ出しはありませんでした。
- 既存食材11件を保持し、既存食材のカテゴリ保存を実際に確認しました。
- 買い物のテスト用メモを追加し、数量・単位の編集、購入済みチェック、ページ再読み込み後の状態保持、削除を実際に確認しました。確認用メモは片付け済みです。
- DB側でも一時データを使い、世帯メンバーの読み取り・更新、他世帯の読み取り・書き込み拒否を検証しました。検証はロールバックし、データを残していません。
- 現在の共有先はメンバー1人でした。もう一方のアカウントは右上の家族設定から招待コードで同じ世帯に参加できます。実際の2アカウント・2端末での同時操作は未確認です。
- 新UIから献立関数へ到達することを確認しましたが、実生成の試行ではGoogle Geminiが一時的にHTTP 503を返しました。既存の関数・モデル・プロンプトは変えず、新UI側では混雑と再試行の案内を表示します。献立カード・料理別詳細は自動テストで確認済みです。
- 写真の選択・画像圧縮・recognize-ingredients呼び出し・候補確認・一括登録の既存処理を引き継ぎました。今回、実写真を送信しての読み取りは再実行していません。
