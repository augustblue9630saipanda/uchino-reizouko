# 冷蔵庫の量・重複確認・リスト表示（2026-11-23）

- 冷蔵庫は1食材1行。食材名の右の「少・並・多」で量を変更し、「…」から名前・カテゴリ・量の編集や削除を行う。
- `ingredients.quantity_level` は `low / normal / high`。既存・新規は初期値 `normal`（並）。量を変えるとSupabaseへ保存し、家族は冷蔵庫を開く・アプリ復帰・表示中の再読込で更新を確認できる。
- 手入力と写真候補の追加は `add_pantry_items` を使用。DB側で現在の同じ世帯の在庫と比較し、Unicode NFKC、空白除去、大文字小文字の違いを吸収する。例：前後の空白、全角英数字、半角カタカナ。別名・同義語まで同じ食材とは判定しない。
- 重複があれば保存せず、3つの選択肢を表示する。「別の項目として追加」は別レコードとして登録、「追加しない」は今回の登録全体をキャンセル、「戻る」は入力や写真候補を保持したまま元の画面へ戻る。
- 写真で複数候補を登録する場合も、確認前に一部だけ登録しない。重複確認には今回の候補内での表記揺れも含む。
- 保存関数は世帯単位のトランザクションロックを取り、重複確認と登録をひとつのトランザクションで行う。公開実行権限は削除し、ログインと既存の世帯所属チェックを必須にする。
- 既存の重複レコードや登録食材を削除・統合しない。RLSを維持し、量の更新権限だけを追加する。
- AI献立の生成仕様は変更しない。将来は `quantity_level` を在庫と一緒に渡せる。少・並・多は主観的な目安なのでgや個数に換算しない。

## 確認

- `node --test tests/*.test.mjs`：既存機能に加え、新規登録・重複時の3選択肢・写真バッチ・量の保存と失敗・共有先切り替えの回帰テスト。
- `supabase/tests/pantry-quantity-duplicates.sql`：正規化、確認前の登録なし、明示的な重複許可、バッチの原子性、量の初期値、夫婦間の変更、世帯外拒否。テスト用の行はロールバックし、既存データを変更しない。
- 古い画面のままの場合はPWAを開き直すか、Safariで再読み込みする。PWAの追加し直しは不要。
