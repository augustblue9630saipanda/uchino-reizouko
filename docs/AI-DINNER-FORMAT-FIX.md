# AI献立の形式エラー修正（2026-11-18）

## 確認した原因

公開アプリのログイン済みアカウントで生成を実行し、Supabaseの実行ログを確認した。
`dinner_validation_failed` の記録は `$.patterns[0].dishes[1].steps` / `array_count`。
生成結果の最初の献立の2品目の手順数が、サーバーの2〜15項目という条件に合わず、応答全体が502になっていた。

Gemini用の軽量スキーマでは、過去のスキーマ複雑度エラーを避けるため配列長などの制約を省いていた。一方、サーバーは厳密に検証するため、生成指示と検証条件に差があった。フロントエンドはサーバーのエラーを表示しており、認証や世帯共有が原因ではない。

## 修正

- 軽量スキーマのdescriptionと日本語プロンプトに配列数・文字数・空値禁止を明記。stepsは簡単な副菜や汁物でも2〜15項目にする。
- サーバーの必須項目、3パターン・各3品、材料と分量、手順、取り分け番号などの検証を維持。
- 全角・大文字・互換文字のg/ml表記は意味を変えずに判定する。
- 形式不備のみ、直前のJSONと失敗した箇所をGeminiに返して最大1回修正する。全体の生成タイムアウトは75秒を共有。通常は1回、形式修正時のみ最大2回のGemini呼び出し。
- HTTPエラー、利用上限、途中で打ち切られた応答は自動再試行しない。
- 実行ログには既知の項目パスとエラー分類、試行回数、コード版だけを残す。食材名、レシピ本文、アカウント情報、認証トークン、APIキーは記録しない。

献立の家族設定・幼児の取り分け・加熱確認・大人の仕上げなど既存の品質指示は維持。認証、世帯共有、写真認識、DB、保存済み食材に変更なし。

## 検証

- `node --test tests/*.test.mjs`: 27件成功。
- 不足した手順の修正成功、2回での打ち切り、HTTPエラーの再試行禁止、共通タイムアウト、単位の表記揺れ、世帯権限、画面の3カード・レシピ表示、ログイン関連の回帰確認を含む。
- 本番の `generate-dinner` に配置済み。実生成の確認結果は追記する。
