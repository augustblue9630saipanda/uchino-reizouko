# 献立リクエスト・冷蔵庫の日付と削除

## 使い方

- AI献立のリクエスト欄は任意。気分は複数選択でき、自由入力と併用できる。
- 買い足し条件は「バランスよく提案」が初期値。「冷蔵庫の食材だけ」は基本調味料を家に置いているか確認する前提。正確な残量は不明なので、材料が足りるかは調理前に確認する。
- 通常は3案。冷蔵庫だけのモードで成立する案が3件未満の場合は、実在する食材名とサーバー照合できた案のみ表示し、件数不足の説明を出す。食材がないのに買い足し不要とは表示しない。
- 各カードには買い足しの有無と食材名、レシピ詳細には必要量と使う料理を表示する。
- 冷蔵庫は登録日を食材名の下に表示。「…」の編集画面で日付を変えられ、空欄は不明になる。通常編集や残量変更では登録日をリセットしない。
- カテゴリ別は折りたたみ可能。古い順・新しい順はカテゴリを横断し、日付不明は最後。検索とカテゴリの絞り込みも併用できる。
- ゴミ箱は1件削除、「選択」は複数削除。どちらも対象件数・名前を確認してから削除する。「表示中をすべて選択」は検索とカテゴリで絞り込んだ結果が対象。選択はフィルター変更後も維持されるので件数と確認画面で対象を確認する。

## データと安全性

- `ingredients.registered_on` はJSTのdate。既存行は実際のcreated_atから移行し、不明な日時は捏造しない。新規登録は日本時間の今日。
- 既存の世帯RLSを継続。登録日の更新も世帯内のみ。削除はID集合とhousehold_idの両方で制限する。
- 料理リクエスト400文字、気分は許可済み7種類、買い足し条件は3種類のみ。食材名・残量・登録経過日数はサーバーがRLS付きでDBから取得する。クライアントの在庫配列は受理しない。
- 残量と経過日数は目安。日付は賞味期限ではなく、食材の安全性を保証しない。Geminiキーは引き続きサーバーシークレットのみ。
- 日付・残量・在庫名の変更後は献立の再生成を案内する。夫婦間の更新は画面切替・フォーカス復帰・20秒ごとの再取得で反映される。
- 本文などをログに追加せず、既存のログイン・共有関係・買い物・写真認識・ご意見メモ・PWA構成は維持する。

## 配置と検証

1. `supabase/migrations/202611240001_pantry_registered_on.sql` を一度適用。
2. `node scripts/build-dinner-server.mjs` でダッシュボード配置用ファイルを再生成。`supabase/dashboard/generate-dinner.ts` を本番のgenerate-dinnerへ配置。写真認識やJWT設定は変更不要。
3. GitHub mainの画面変更をPagesへ反映。
4. `node --test tests/*.test.mjs`。DBの共有・日付・削除は `supabase/tests/pantry-registration-sharing.sql` でロールバック付き検証。既存の重複登録テストも継続。

iPhone実機のPWA、WindowsにインストールしたPWA、夫婦の端末間の実操作は、ブラウザの画面幅テストやDB権限テストとは別に確認する。ブラウザ幅だけで実機確認済みとはしない。

## 2026-11-24の確認結果

- 自動テスト54件成功。買い足し条件・リクエスト送信、JST日付境界、並び替え、不明日付、削除確認・キャンセル・世帯切替、既存機能を検証。
- 本番DBで、夫婦両方の権限による日付編集・削除と、世帯外の拒否をロールバック付きで確認。既存の重複確認・明示追加・原子的なまとめ登録のDBテストも再実行して成功。
- 本番画面で確認用の2件だけを作り、登録日変更・不明表示・残量変更後の日付維持・個別削除の取り消し・絞り込んだ2件の選択と一括削除を確認。確認用データは削除済みで、元の食材は削除・統合していない。
- 320px・390pxのブラウザ幅で横はみ出しがなく、食材行は44px。アイコンと直接操作を維持。狭い幅では一部ボタンの幅のみ調整。
- 実際のGemini生成で、カレーのリクエスト＋複数の気分＋バランスモードから「在庫の豆腐・卵の和風あんかけ」「買い足しのポークカレー」「豚肉とにらの野菜炒め」の3案を確認。
- 最終版の在庫のみモード・リクエストなしでは、卵とじ、れんこんと玉ねぎのチーズ焼き、にらと豆腐の卵炒めを主菜にした3案を確認。全案が主な食材の買い足し不要。
- 実生成ログから、簡単な副菜の1手順が旧形式制約で落ちるケースを修正。副菜は全フィールドを維持した1手順を許可し、主菜・汁物は2手順以上を維持。大人の仕上げに明示的な「分量外」があれば、既存の上限内で修正を求める。
- 買い足しありなしの見直しと形式修正は、共通で最大2回・75秒の既存枠内。調味料に括弧で用途が付いた場合の誤判定も修正。正確な残量や安全性を保証するものではない。
- 公開ファイルの一致、PWAマニフェスト・起動URL・アイコンの維持を確認。iPhone/Windowsのインストール済みPWA実機、夫婦2端末での同時操作は未確認。買い足しOKは自動テストで送信と処理を確認したが、専用の実生成試験は未実施。
